# crawlsnap-js

Official JavaScript / TypeScript SDK for the **CrawlSnap** data intelligence
platform. Published on npm as **`crawlsnap`** (unscoped); repo
`github.com/crawlsnap/crawlsnap-js` (public).

This is the JS sibling of the canonical Python SDK at `~/Dev/crawlsnap-python`.
When in doubt about behavior, mirror the Python SDK adapted to JS idioms. The
language-agnostic contract lives in the `write-sdk` skill's
`references/sdk-spec.md` (in the main `crawlsnap` repo).

## Architecture: facade over generated models

```
src/
  index.ts       # public entry: exports CrawlSnap, errors, types, VERSION (NO init())
  client.ts      # CrawlSnap class: fetch pipeline, retries, abort/timeout merge
  base.ts        # IO-free: envelope unwrap, status→error map, backoff math, sleep
  resources.ts   # vectorSnap / pulseSnap / subdoSnap + .v1 pinning + scanIter
  errors.ts      # CrawlSnapError hierarchy (thrown, instanceof)
  types.ts       # friendly aliases re-exported over models.ts
  models.ts      # GENERATED by openapi-typescript — NEVER hand-edit
  version.ts     # VERSION constant (keep in sync with package.json)
```

- **`models.ts` is generated**, the rest is **hand-written**. Never hand-edit
  `models.ts`; never hand-type payload models. Run `npm run regenerate` after the
  contract changes (it re-bundles + regenerates only `models.ts`).
- **Source of truth for endpoints/types:** the public contract bundle
  `~/Dev/crawlsnap-contracts/dist/crawlsnap-v1.yaml` (produce with
  `cd ~/Dev/crawlsnap-contracts && make bundle`).
- Keep IO-free logic in `base.ts` so envelope/error/backoff lives in one place.

## Design decisions (and divergences — do not "fix" these)

- **No `init()` global singleton.** Entry point is explicit `new CrawlSnap({...})`
  ONLY — matches OpenAI/Anthropic/Stripe. This deliberately overrides the
  `write-sdk` skill's "ship init() in JS" step.
- **Named exports only**, no default export (avoids CJS/ESM `.default` friction).
- **Types via `openapi-typescript`, cast-only** — no runtime validation (no zod).
  Payloads are cast to the generated types.
- **Native `fetch`, zero runtime dependencies**; injectable via
  `new CrawlSnap({ fetch })`. Node 20+ (uses `AbortSignal.any`/`timeout`).
- **Single client** (JS is async-by-default) — no sync/async twin. Use
  `Promise.all` for concurrency.
- **Throw typed errors**, never return `{ data, error }`. Narrow with
  `instanceof`. Hierarchy mirrors Python: `CrawlSnapError` →
  `APIConnectionError`/`APITimeoutError` and `APIStatusError` → Bad/Auth/
  QuotaExceeded/SubscriptionInactive/NotFound/RateLimit/Server.
- **Per-call options:** `{ signal, timeout, maxRetries, rawResponse }`. Constructor
  option casing is `baseURL` (not `baseUrl`).
- **Per-product API versioning:** version is a *value*, not a class. `.v1` getter
  returns a lazily-cached, same-type instance pinned to that version
  (`DEFAULT_VERSION` in `resources.ts`). Default is stable — bumping it is a
  deliberate, changelogged release; never a client-wide switch.
- **Payload field casing stays wire-format (snake_case, e.g. `as_owner`)** like
  OpenAI/Stripe. Only the SDK surface (client, resources, methods, options) is
  camelCase.

## Naming rules (customer-facing)

- Resource families are the brands **VectorSnap / PulseSnap / SubdoSnap** —
  never "scan" or the raw URL path. In JS: `vectorSnap`, `pulseSnap`, `subdoSnap`.
- **No upstream source/vendor names** anywhere (code, docs, README, examples):
  no VirusTotal/AlienVault/OTX/URLHaus/Hybrid Analysis/Cuckoo. Use generic
  language ("reputation enrichment", "threat-intelligence pulse").
- All code, comments, strings, and docs in **English**.

## Commands

```bash
npm run build       # tsup → dual ESM (.js) + CJS (.cjs) + .d.ts/.d.cts
npm run typecheck   # tsc --noEmit
npm test            # vitest, mocked fetch — no network
npm run regenerate  # re-bundle contract + regenerate src/models.ts
```

- Tests use a **mocked `fetch`** (no network). Cover: success unwrap, 404/402,
  429-retry-then-success, rate-limit-exhausted, pagination, rawResponse,
  missing-key, timeout→`APITimeoutError`, user-abort propagates without retry,
  version pinning (cached + stable default).
- `tsconfig` has `stripInternal: true` so the internal `request()` method does
  NOT leak into the public `.d.ts`. Keep it `@internal`.
- `package.json` ships only `dist/` (verify with `npm pack --dry-run`).

## Publishing (npm Trusted Publishing / OIDC)

Releases publish from CI on a GitHub Release, token-free, with provenance:

1. Bump the version in **both** `package.json` and `src/version.ts`, then
   `npm install` to sync the lock.
2. Move the `## [Unreleased]` entries in `CHANGELOG.md` under the new version
   heading, then commit + push.
3. `gh release create vX.Y.Z --title vX.Y.Z --notes ""` — the body is filled in
   by CI from `CHANGELOG.md`, so leave it empty.
4. `.github/workflows/release.yml` runs build+test and
   `npm publish --provenance --access public` via the OIDC token exchange
   (no `NODE_AUTH_TOKEN`). `publishConfig.provenance: true` enforces provenance —
   so do NOT `npm publish` from local (it fails without a CI provider; the
   original v0.1.0 was a one-time `--provenance=false` bootstrap).
5. Verify: `npm view crawlsnap version` and `npm audit signatures`.

The trusted publisher is configured on npmjs.com for the `crawlsnap` package
(GitHub Actions → `crawlsnap/crawlsnap-js` → `release.yml`).

## Releases & changelog

`CHANGELOG.md` is the single source of truth for release notes. Every
user-visible change is written into it **in the same commit that makes the
change** — never generated from commit messages afterwards.

- Format: [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) 1.1.0.
  Version headings are `## [x.y.z] - YYYY-MM-DD` (ISO date, newest first) and
  the only section headings allowed are `Added`, `Changed`, `Deprecated`,
  `Removed`, `Fixed`, `Security` and `Breaking`.
- Work in progress goes under `## [Unreleased]`. Cutting a release renames that
  heading to the new version plus today's date, adds a fresh empty
  `## [Unreleased]`, and updates the link definitions at the bottom of the file.
- Every released version starts with a `Contract: crawlsnap-contracts vX.Y.Z`
  line, so an SDK version can always be traced back to the API contract it was
  generated from.
- Write for humans: what changed for a caller and why, not which files moved.
- Pre-1.0 the package uses lenient semver — a minor version may break; when it
  does, say so under a `Breaking` heading.
- The `release-notes` job in `release.yml` copies the tagged section into the
  GitHub Release body. Never write release notes by hand in the GitHub UI: they
  are overwritten. A tag with no matching CHANGELOG section fails the job on
  purpose.
- npm renders only the README, so the README's `## Changelog` section is the
  only pointer npm users get. Its links must be absolute.

## When changing things

- Adding/altering an endpoint or payload: update the contract in
  `crawlsnap-contracts`, `make bundle`, `npm run regenerate`, then adjust the
  hand-written resource method in `resources.ts`. Add a mocked test.
- Adding a new API version (e.g. v2): add a `get v2()` accessor returning
  `this.pinned("v2")`, regenerate models, and only bump `DEFAULT_VERSION` in a
  deliberate release when ready to retarget unpinned callers.
- Keep the README and this file in sync with real behavior after notable changes.
